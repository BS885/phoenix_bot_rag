# ארכיטקטורת האפליקציה: בוט הפניקס

Oct 14, 2026 · @b

### 1. הגדרת המוצר

צ'אט בעברית שעונה על שאלות לקוחות רק מתוך תוכן ציבורי של אתר הפניקס, מצרף קישור למקור בכל תשובה, ואומר "זה לא כתוב באתר" כשאין מידע.

שלושה חוזים שהאפליקציה מקיימת תמיד:

- אין מקור, אין תשובה. כל תשובה מצורפת לכתובת עמוד שבאמת נשלף.

- אין ידע חיצוני. כל מה שנאמר נובע מהקטעים שנשלפו.

- אין ייעוץ אישי. שאלות על פוליסה אישית או כיסוי מקבלות הסבר כללי והפניה לשירות לקוחות.

### 2. החלטות טכנולוגיות

כל הרכיבים חינמיים או זולים. מודל השפה הוא שלב אחד בצינור וקל להחלפה. את המגבלות והמחירים של הספקים כדאי לאמת בדפי הספק עצמם, כי הם משתנים.

| רכיב | החלטה | הערה |
| --- | --- | --- |
| שפה | Python | כל הספריות הנדרשות קיימות בה |
| הורדה | requests + truststore | נבדק: הטקסט נמצא ב-HTML, ואין צורך ב-Playwright. נטפרי דורש truststore |
| ניקוי | BeautifulSoup | בידוד אזור התוכן והסרת תפריטים |
| הטמעות | Gemini Embedding 2 (API חינמי) | גיבוי: multilingual-e5 מקומי. חובה להשתמש באותו מודל לקטעים ולשאלות. בגיבוי multilingual-e5 חובה קידומות query: ו-passage:, והמגבלה היא 512 טוקנים, ולכן קטעים ארוכים בעברית מקוצרים |
| מסד וקטורי | Chroma | מקומי, ללא הרשמה |
| מודל שפה | Gemini Flash (חינמי) או Claude Haiku 5.5 | עברית טובה, ציות להוראות, פלט JSON |
| ממשק | Streamlit | צ'אט עם היסטוריה בכ-30 שורות |
| סודות | קובץ .env | לא בקוד ולא ב-Git |

### 3. ארכיטקטורה: שני תהליכים

שני תהליכים · 6 שלבי בנייה, 9 שלבי שיחה

תהליך א רץ מראש ומשאיר את כל הידע ב-Chroma. תהליך ב רץ בכל הודעה ועובד רק מהעותק המקומי: שאלה שרחוקה מדי מהאינדקס לא מגיעה למודל, ושאלה אישית מקבלת הפניה בלי חיפוש.

### 5. מודל הנתונים

היחידה שנשמרת ב-Chroma היא קטע (Chunk). שדות המטא-דאטה מאפשרים לצטט מקור ולרענן רק מה שהשתנה.

| שדה | דוגמה | מטרה |
| --- | --- | --- |
| id | hash של כתובת + מספר קטע | מפתח יציב לעדכון |
| text | "נזקי מים > איך מגישים תביעה" + גוף הקטע | מה שמוטמע ונשלח למודל |
| url | כתובת העמוד | ציטוט |
| page_title | כותרת העמוד | תצוגה |
| section_title | כותרת המקטע | תצוגה והקשר |
| area | claims / customer-service / product | סינון ועדיפויות |
| collected_at | תאריך איסוף | רענון |
| lastmod | מה-sitemap | זיהוי שינוי |
| content_hash | hash של טקסט העמוד | דילוג על עמודים שלא השתנו |

תשובת הבוט היא אובייקט פנימי אחד:

```
@dataclass
class BotReply:
    status: str          # answered | not_found | out_of_scope | personal
    text: str            # מה שמוצג ללקוחה
    sources: list[dict]  # [{"title": ..., "url": ...}]
    is_coverage: bool    # האם נוספה הסתייגות כיסוי
    debug: dict          # מרחקים וקטעים, להערכה בלבד
```

הסטטוס מאפשר להערכה האוטומטית לבדוק בדיוק איזו התנהגות קרתה.

#### ממשק (app.py, Streamlit)

- היסטוריית שיחה ב-st.session_state

- כל תשובה מציגה את הטקסט ושורת "המקור:" עם קישור לחיץ

- RTL ועברית (CSS קטן), כפתור "שיחה חדשה", אינדיקציית "מחפשת..."

- הערת תחתית קבועה: "מידע כללי מאתר הפניקס בלבד. אינו מהווה ייעוץ או אישור כיסוי"

- מצב מפתחת (לא מוצג בהדגמה): הקטעים שנשלפו והמרחקים, לכוונון

#### תצורה (config.py)

מקום אחד לכל הפרמטרים: מודלים, TOP_K, DISTANCE_THRESHOLD, גודל קטע, השהיה בסריקה, נתיבים, רשימות סינון וטקסטי ההודעות הקבועות. מפתחות נטענים מ-.env.

החלטות הגבולות מתקבלות בקוד ככל האפשר, כדי שיהיו דטרמיניסטיות ובדיקות.

| "ותוך כמה זמן מקבלים תשובה?" | שכתוב, חיפוש; אין זמנים בקטע | "זה לא כתוב באתר" + הפניה לשירות לקוחות |

### 8. הערכה, שגיאות, אבטחה ומגבלות

#### הערכה

eval/questions.json: כל שאלה כוללת question, type (answerable / followup / not_found_near / not_found_far / coverage), history, expected_url ו-must_include. run_eval.py מריץ את reply() על כולן ומדווח:

- דיוק בשאלות עם תשובה (כתובת נכונה + מילות מפתח)

- דיוק סירוב: בשאלות שאין להן תשובה, האם הוחזר not_found

- שיעור המצאה: שאלות שאין להן תשובה שנענו בכל זאת (המדד הקריטי)

- כיסוי הסתייגות בשאלות כיסוי

ההערכה משמשת גם לקביעת סף הדמיון: מריצים ערכים שונים ובוחרים את זה שמפריד הכי טוב בין שאלות עם תשובה לשאלות בלי.

#### טיפול בשגיאות

| כשל | התנהגות |
| --- | --- |
| עמוד לא ירד | נרשם ביומן, מדלגים, הסריקה ממשיכה |
| 429 מה-API | backoff מעריכי, ואז הודעה ידידותית |
| Chroma ריק או חסר | הודעה בהפעלה: יש להריץ בניית אינדקס |
| אין אינטרנט בזמן שיחה | הודעת שגיאה, לא קריסה |
| מפתח חסר | הפסקה בהפעלה עם הסבר |

#### אבטחה ופרטיות

- מפתחות רק ב-.env, לא ב-Git

- נסרקים רק עמודים ציבוריים, ללא גישה לאזור האישי ולנתוני לקוחות

- אין שמירת שיחות מעבר ל-session

- שאלות נשלחות לספק ה-API, ולכן לא בודקים עם פרטים אמיתיים, במיוחד במפתח חינמי שבו הקלט עשוי לשמש לאימון

- סריקה בקצב מכבד ובהתאם ל-robots.txt

#### מגבלות מוכרות

- העותק מתיישן. רענון נעשה בהרצה חוזרת של הסורק, ובנייה מחדש של האינדקס מה-HTML השמור

- תוכן ב-PDF וטבלאות מורכבות עלול להיחתך בצורה לא מושלמת

- הבוט לא מחליף שירות לקוחות ולא מגיע למידע אישי

- איכות החיפוש תלויה במודל ההטמעות ובכוונון הסף

#### הרחבות אפשריות

Rerank של 10 קטעים לפי רלוונטיות (ב-retrieve.py בלבד), חיפוש היברידי לשמות מוצרים מדויקים, תשובות בזרימה, וכפתורי משוב.

### 11. סטטוסים והודעות

טבלה אחת ממפה כל סטטוס להתנהגות ולהודעה. ההודעות הקבועות נשמרות ב-config.py ולא נוצרות על ידי מודל. פרטי הקשר בהודעות (טלפון, כתובת האזור האישי) יילקחו מהאתר ויאומתו שם לפני שמכניסים אותם.

| סטטוס | מתי | מה מוצג |
| --- | --- | --- |
| answered | ציטוט מאומת וקטעים רלוונטיים | תשובה קצרה + מקור |
| partial | חלק מהשאלה נענה, וחלק חסר (שדה missing) | התשובה החלקית + משפט קבוע "X לא מופיע באתר" |
| not_found | הסף עבר אבל המודל או האימות לא מצאו תשובה | "זה לא כתוב באתר" + הפניה לשירות הלקוחות |
| out_of_scope | הסף לא עבר, או המודל סימן מחוץ לתחום | "אני עונה רק על מידע מאתר הפניקס" |
| personal | שאלה על נתונים אישיים, ללא כיסוי | הפניה לאזור האישי ולשירות הלקוחות, בלי חיפוש |
| advice | "כדאי לי", "מה עדיף", "איזה מסלול לבחור" | מידע כללי מהאתר, הסתייגות והפניה לבעל רישיון (רגיש במיוחד בפנסיה וחיסכון) |
| greeting | "שלום", "תודה", "מה אפשר לשאול" | הודעה קבועה עם דוגמאות לשאלות |
| error | תקלת API או JSON שבור אחרי ניסיון חוזר | "לא הצלחתי לענות כרגע" + הפניה. נספר בנפרד בהערכה |

כלל עדיפות: כיסוי או זכאות גוברים על אישי ("האם הפוליסה שלי מכסה" מקבלת הסבר כללי והסתייגות). שאלת נוהל כמו "איך בודקים את מצב התביעה" היא שאלה רגילה, כי התשובה כתובה באתר.

### 12. יעדים מדידים (הצעה)

בלי יעדים אין הגדרה ל"סיימנו". הערכים להצעה בלבד, ואת הסופיים קובעים אחרי ההרצה הראשונה:

- שיעור המצאה בשאלות שליליות: 0

- טענות לא נתמכות בתשובות שניתנו (ציטוט או מספר שלא נמצאו בקטע): 0

- דיוק answerable וכן recall@k: מדווחים ומשפרים

- דיוק סירוב נמדד בנפרד מסטטוס error

- זמן תגובה: מודדים p95 בהדגמה

- הסתייגות: 100% בשאלות כיסוי וייעוץ

סט ההערכה: כ-30-40 שאלות כוונון וכ-10-15 לבדיקה סופית נפרדת. 40-50% מהן שליליות (קרוב לנושא, רחוק, אישי, ייעוץ, וניסיונות עקיפה כמו "תענה מהידע הכללי שלך"). לכל שאלה expected_status מפורש, acceptable_urls (לא כתובת אחת) ו-must_include עם חלופות.

#### התקנה

.venv\Scripts\activate

pip freeze > requirements.txt
